# V4 INT8-36 原型：实现验证与精度失败

这是独立实验后端，未进入公共 GEMM dispatch，也没有修改冻结 V3。源代码在 `bench/8454h/roofline_v4/int8_proto/`。原型使用手写 `TDPBSSD` 汇编和 AVX-512 分片打包，36 个整数产品、8 个整数对角线；所有 K 的贡献保持 INT32，最后以 INT128 加权并显式舍入到 double。

## 修复与证据

首次构建成功，但数值 gate 在 K=63 中止。随后完整的 scalar/AVX-512 对照 probe 定位到最高数位处理错误：低七位应取 `[-64,63]`，最高位应直接保存并允许 `[-64,+64]`。对最高位继续取 radix-128 余数会把合法的 +64 写成 −64，并产生一个被错误拒绝的 carry。修复保留原 scale `55-e`，没有减少量化位数。

首次执行前还修复了 AMX tile 配置布局：`colsb` 偏移 16、`rows` 偏移 48、结构大小 64，均以静态断言约束。并行打包按 A 的 M32、B 的 N32 分区首次触页；工作区采用一个连续、按 worker 固定偏移的分配，避免超出缓存槽位及复用时交换 worker 页归属。

修复后，在相同输入上 scalar 与 SIMD 数位一致，最高位与 RNE 边界 probe 通过；完整 16 个数值 case 都能执行，不再出现分片范围异常。别名、行 padding、拒绝非法输入时 C 不变以及 K=0 检查通过。质量程序在数值 case 抛异常时保留对应错误并继续，保证失败清单为完整合法 JSON；精度门槛未改变。

## 仍未通过精度门槛

gate 使用完整 32×32 输出的 binary128 参考，`e_scaled=max_ij |error_ij|/(|A||B|)_ij`。预设标准化误差门槛为 binary64 epsilon，约 `2.22e-16`；与 V3 p21 的比较作为另一项独立字段保留。此门槛比冻结 V3 在某些输入上的结果更严格，不能用 gate 失败反推 V3 达到 binary64 精度。

| 失败 case | e_scaled | 观察 |
|---|---:|---|
| uniform，K=1 | 8.42e-14 | 小分母放大编码/截断产生的绝对误差；尚未分别量化输入舍入与遗漏产品的贡献；该 case 仍满足独立的 V3 比较条件 |
| sparse，K=257 | 1.33e-15 | 有效点积项少，量化误差未被长点积摊薄 |
| reciprocal dynamic range，K=257 | 0.291 | A/B 的指数在 K 上互相抵消，全局定点尺度丢失了本来有贡献的产品 |

其余 13 个 case 满足该门槛，包括 uniform 的 K=63/64/65/255/256/257/4096/32768、Gaussian、零、抵消、RNE 边界和有限极值。有限极值 case 中原型成功且精确，V3 调用拒绝输入/中间结果，因此不能把它记作两者精度比较通过。

完整修复版记录、源码快照、probe、库和程序哈希位于 `bench/8454h/roofline_v4/int8_proto/results/20261014T091812Z-4-topdigit-fix/`；此前失败尝试保留在同级目录。总体 gate 返回失败，**没有采集 INT8 原型的性能矩阵，不能给出实际加速比，也不能替换通用 FP64 路径**。

整数无溢出的证明仍成立，精度失败来自编码/截断而非 INT32 overflow。下一步若继续该方向，需要明确输入范围或采用能保留动态范围的编码/校正方法，并重新计算实际产品数和重建成本。当前 BF16 搜索继续采用与 V3 严格逐字节一致的候选。
