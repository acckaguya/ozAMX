## 当前实施方案复核：有限域方案已替代原±1提案

当前代码采用p=2147483647，每个输出完成后通过getrandom生成三个完整随机向量。uint32值x若≥2p则拒绝，随后x mod p；接受区间[0,2p)中每个余数恰有两个原像，故在随机源均匀独立的假设下严格均匀。这里的随机源独立性是概率模型假设，不是本报告证明操作系统随机源物理独立。

扫描先拒绝非有限值，再要求256*C严格为整数、绝对值≤64N，最后转换整数；真实整数结果同样在此范围。因此错误矩阵D的每个元素绝对值≤128N。在当前硬编码N=128/1024/4096下，128N<p，非零整数D不可能全部模p变成零。这是该方案必不可少的边界：若未来移除输出范围检查或扩大维度，不能继续照抄此概率保证。

对非零域矩阵D，取非零行的一个非零系数，固定其它坐标后恰有一个r坐标取值能使该行内积为零。因此单次P(Dr=0)≤1/p，三个独立向量漏检≤p^-3，约1.01e-28。该界是每个错误输出的界；q个输出的保守整体界为q/p³。代码每个调用后立即validate，随后抽取新挑战，符合非自适应错误输出的要求。它不是确定性逐元素证明，但比原8次±1提案明显更强。

整数安全也成立：左侧sum(C_integer*r)的绝对中间和<64N²p，N=4096时<2^61；B*r的绝对和<8Np，取mod后每项在[0,p)，右侧sum(a*br)的绝对和<8Np。代码在乘前显式转int64，没有先用int32完成乘法。ci的int32存储因|ci|≤64N≤262144安全。n≤128另执行完整int64三重循环参考，且仍保留域检查。

## 原提案结论（历史，挑战方案已被上节替代）

该方案经过下列补强后，足以用独立工作量、独立计时和独立整数参考识别1000倍单位错、旧输出复用及大范围漏算：每个计时调用立即在计时外验证其输出；时间、维度、操作数及单位原值保留；Freivalds挑战新鲜独立且建议从8次提高至32或64次；整数范围和转换严格检查。它仍不是对4096³结果逐元素确定性证明，也不能凭dyadic输入性能宣称普通随机浮点输入的全部性能和精度已验证。

8次±1挑战的单次错误输出最坏漏检率上界是1/256，约0.390625%。这对于严肃独立审计偏弱；32次为2^-32，64次为2^-64。在错误非自适应且挑战独立的条件下，增加挑战的数学收益明确，校验都在计时外，不改变吞吐时间边界。

## 1. dyadic精确性条件成立，但输入更新也必须保持条件

设 A=a/16、B=b/16，整数a,b均在[-8,8]，则精确输出为 C=S/256，其中 Sij=sum_k aik*bkj。对于K≤8192，任意部分和的绝对整数值≤64K≤524288<2^24。BF16可精确存储输入，乘积和所有正常范围内FP32部分和也都可精确存储。因此任意归约树的BF16×BF16→FP32、SGEMM，以及正确执行的三片FP32路径，都应得到同一个精确C。

此时FP32 residual分解的低片为零，六产品形式可能退化为主片贡献加零。数值检查很强，但它对低残差片、跨尺度累加的覆盖很弱。仍需普通全FP32输入的独立诊断。

每rep改变A一个元素时，必须从相同17值集合选择一个不同的新值，且在被测存储类型中也确实不同。整数镜像a和浮点A必须同步更新；记录坐标、旧值、新值及当前输入摘要。不要在计时内改输入。确保变化影响输出：例如改变的A列对应B行不能全零，且至少一个预期输出变化非零。随机生成通常满足，但审计应直接断言。

参考整数矩阵必须来自原始生成规则或浮点值的独立精确反解并交叉核对。若参考与被测输入共用同一个错误索引转换，校验会失去一部分独立性。

## 2. 完整整数参考与大矩阵扫描

N≤128完整int64三重循环参考不使用MKL，非常适合作为首个确定性验证。保持简单的独立行列索引、独立输出缓冲，不复用生产pack或微核辅助函数。包含矩形小例可另外覆盖stride/索引，但不是验证4096方阵吞吐的必要前提。

大矩阵每个输出必须先依次满足：

1. C有限；
2. 256*C是精确整数，无容差舍入；
3. |256*C|≤64K；
4. 通过后才转int64并进入Freivalds。

可在double中计算256*C以简化检查，但不得把NaN/Inf或超界浮点直接转整数。范围检查使用整数维度提升到int64后计算。别只扫描一个象限、一个stride或“有效非零项”；每个M×N输出都应参与。poison C应写满实际输出区域，推荐NaN；若beta=0，此调用应覆盖结果。缓冲区边界canary可作为独立内存检查，但不能替代数值扫描。

扫描“有限整数且界内”单独并不证明正确。全零输出或遗漏一部分K仍可能通过，必须与后面的等式校验一起解释。

## 3. ±1 Freivalds的保证、限制与整数溢出

对当前输出定义整数差矩阵 D=a*b-S。若D非零，取其任意非零行及一个非零系数Dij。固定该行其余随机符号后，rj∈{-1,+1}最多一个取值能使该行内积为零，因为两个候选相差2Dij≠0。因此P(Dr=0)≤1/2。独立重复t次，漏检概率≤2^-t。该证明在整数/实数精确运算上成立，并不要求使用{0,1}而排除±1。

必要条件：

- 每个向量的各坐标独立、公平；各向量独立。
- 待检矩阵D在抽取挑战前已经固定。对每个输出完成计算后再生成独立挑战最清晰。
- 被测实现不能根据挑战修改输出。不要把挑战buffer或相关seed传给被测例程。
- 验证全部输出行的等式，不抽样行。
- 两侧的整数计算精确，没有signed overflow、浮点转换或模数导致的未分析碰撞。

计算形式应为 `a*(b*r)` 与 `S*r`，其中a,b是未除16的整数输入，S=256*C，不能遗漏尺度。对方阵N：|b*r|≤8N；第二层和|a*(b*r)|及|S*r|≤64N²。N=4096上界为1,073,741,824；N=8192上界为4,294,967,296，已超过int32。统一使用int64累加和乘法，乘法操作数在乘之前提升，避免“先int32相乘再转int64”。一般矩形上界为64KN；启动时校验它小于INT64_MAX。

验证q个错误输出时，整体“至少一次错误输出被漏过”的保守union bound为q*2^-t。不能把每个rep各8个挑战描述成对任一错误输出80位保证：如果只有一个rep错误，它只得到那8次挑战保护。重新使用固定8个向量也不能自动把重复次数乘进指数。

对大量输出，可采用64个±1挑战，逐输出生成并记录独立seed；若希望第三方复跑，保留seed和生成算法。固定公开seed是工程可复现性，不是面对恶意自适应实现的概率保证。本次目标是非恶意实现错误，仍建议挑战在输出完成后产生，以避免不必要假设。

更强替代是完整int64参考；成本为O(N³)，可能很高。随机有限域向量也能加强保证，但需要明确素数、模运算和宽乘法，复杂度与新出错面更大。当前任务首选增加±1次数，不必引入复杂新校验器。

## 4. 计时、TFLOPS和CPU秒

每个例程完整调用应由同一边界计时，包括该例程承诺的全部工作，不包括输入变更、poison、输出扫描、Freivalds、随机挑战生成及日志。所有例程必须同步完成才能结束计时，不能仅测启动或异步提交。一次warmup后十次调用，并保留全部样本，不挑最快结果作为论文均值。

对每次记录保存N/M/K、开始/结束时间或原始duration、明确duration单位、两个墙钟elapsed、进程CPU秒、例程名称和成功校验状态。独立重算：

```text
F = 2 * int64(M) * int64(N) * int64(K)
GFLOP/s = F / elapsed_seconds / 1e9
TFLOP/s = F / elapsed_seconds / 1e12
GFLOP/s / TFLOP/s = 1000
```

对4096³，F=137,438,953,472；1 TFLOP/s对应约0.137439秒，10 TFLOP/s对应约0.0137439秒。这个秒数反算足以直接揭露1000倍单位错。不得用32位整数计算2N³。若采用2MNK−MN的精确算术计数，必须另列，不应混入论文通用2MNK口径。

MONOTONIC_RAW和steady_clock交叉检查可发现duration转换、代码位置和计时API使用错误，但二者可能基于同一硬件时钟，不能称为完全独立物理计时源。通常两者elapsed应接近，保留采样边界开销；短小N不适合据单次微秒读数判断高精度吞吐。4096的墙钟尺度足以检查单位数量级。

getrusage(RUSAGE_SELF)的用户+系统CPU时间通常包含进程内多线程，可能远大于wall，也可能因等待明显小于“线程数×wall”。CPU秒/wall是平均占用CPU数量的近似诊断，不是GHz，不是核心峰值利用率，也不能证明AMX使用率。吞吐分母必须是wall秒；不得除CPU总秒后仍称应用TFLOPS。使用RUSAGE_THREAD只会观察调用线程，不适合此处。

例程交错随机能减轻固定调用位置和频率漂移偏差，但不能证明环境稳定。记录顺序与每次原始值；吞吐headline若遵循论文协议，应使用F/算术平均wall，而不是先求每次TFLOPS再取平均，两者一般不同。

## 5. 每rep污染输出和改输入的效力

改变A且poison C能揭示未实际执行、旧输出、未覆盖部分输出等问题，但必须每rep在计时后、下一次poison前完成验证。只校验最后一次会漏掉此前错误。改一个元素使一行输出发生变化，不代表其它行每次都独立重算；完整扫描/Freivalds仍是必要项。

若被测实现能够正确缓存不变部分并更新受影响结果，这种重用本身不构成错误，吞吐应明确是连续近似同输入调用的测量。当前普通GEMM通常不提供输入内容缓存，但不能把“正确输出”证明为“每次确实执行了恰好2N³次运算”。2N³是有效数学工作归一化，并非指令计数证明。

如需更强排除跨调用缓存，使用多个独立输入组或每rep改变多处分散元素；相应初始化仍放在计时外，同时记录缓存冷热条件。对于本次检查单位和漏算，现有方案加逐rep独立验证已足够，无须强制扩展大规模输入池。

## 6. dyadic与普通FP32输入的不同结论

dyadic密集随机输入只有17个精确值，且FP32低分片全零。即便矩阵没有稀疏结构，也不能称为典型全FP32精度负载。实现若有全零片快速路径、基于数值的校验、不同压缩或异常分支，运行成本可能变化。应检查或记录路径是否与普通FP32输入一致；不能以dyadic吞吐替代完整论文[-1,1]随机数据的吞吐结论。

普通全FP32小矩阵用完整longdouble dot作为独立诊断合理，但longdouble不自动是精确实数oracle。应打印 `numeric_limits<long double>::digits`，某些环境它与double相同；即使x87 64位有效精度也仍有舍入。指定输入生成、舍入、允许误差指标及参考误差边界；必要时用整数浮点位分解的精确累加或binary128复核少量疑点。不要对一般FP32输入要求与longdouble逐位相同。

大矩阵512个longdouble dot只证明抽样点，无法证明完整矩阵误差范数或所有输出；选择位置应独立随机且覆盖不同块与边缘，保存坐标。它作为dyadic完整矩阵概率验证之外的常规分布补充非常有价值，但应分开报告“精确整数/概率全矩阵验证”和“浮点抽样误差”。不能将512点的采样eF写为完整Frobenius误差。

## 7. 最小交付与可下结论范围

建议新附件至少输出：独立输入生成和seed、小矩阵确定性结果、大矩阵每rep完整扫描统计、每rep32或64个独立挑战全行比较结果、所有原始wall与CPU样本、公式独立重算结果、校验失败立即标记无效的规则。实现代码和编译参数应保存以供复核，不复用原benchmark中的计时/单位换算帮助函数。

通过后可说：“在该密集dyadic输入协议下，输出经独立整数检验，实测秒数与2MNK有效吞吐换算一致，未观察到1000倍单位错、旧输出或漏算；大矩阵随机校验的漏检上界为指定概率。”

不能仅据此说：“所有既有测试正确”“普通随机全矩阵误差已验证”“真实执行了2MNK条算术操作”“已复现论文全部性能”。这套协议是强而清晰的独立审计，不需要承担超出其输入、样本与数学保证的结论。
