## 8. 结论与边界

**结论：论文性能未复现——完整 40 配置测量已完成，所有 FP32 尺寸均未达 Figure 7 点值（0.215/0.154/0.267/0.661/0.882/1.064/0.769/0.811 vs 2.56/2.17/1.70/1.39/1.14/1.16/1.25/1.32）；但严格模拟路径在大 N 明显优于旧自适应路径。**

- 大 N 方向性对比（旧自适应 = V3 40 配置全 API 重算，`docs/audit/COMPREHENSIVE_REVIEW.md` §9.1）：N=2048 0.591→0.661、N=4096 0.631→0.882、N=8192 0.506→1.064、N=16384 0.377→0.769、N=32768 0.507→0.811；小 N 更差：N=256 2.220→0.215、N=512 1.086→0.154、N=1024 0.662→0.267（新路径固定 256 宏块在 N≤1024 只剩 1/4/16 个输出任务，另有六片固定预处理成本）。该对比跨两个批次，只作方向性陈述：COMPREHENSIVE_REVIEW §9.2 记录同库跨批可差 2.43 倍。
- 达标检查器终局：exit 1（`analysis.json` `full_40_configuration_coverage=true`、`paper_protocol_and_identity_valid=true`、`paper_fp32_speedup_targets_all_met=false`）。
- 不能越过的边界（写结论必须保留）：
  1. **Figure 6/7 单位存疑**：轴标 GFLOPS 与图面量级不符（`paper_reference.json` `figure6.unit_caveat`）；本文只用同单位比例与同机墙钟，不擅自换算。

## 9. 独立验收补充（2026-10-16，第三方只读复核）

独立验收 agent 从 40 个 checkpoint 的原始向量重算了全部均值/中位数/SD/min/max、speedup、TFLOP/s 与六组原始向量，与 `results.csv`/`analysis.json` 逐项一致（rel≤2e-9），身份/seed/10 轮/覆盖/夹具对抗全部通过；总判定为：本目录作为“完整、身份冻结、内部一致、诚实未达标”的证据链 accept，论文性能未复现（reject 任何“论文性能已复现”表述）。以下 caveat 必须随数据引用：

1. **fp64 p21 N=32768 存在一个慢样本**（wall 10 轮中 max/median=1.694；样本保留、不剔除）。敏感性：按中位数计该配置 vs DGEMM 为 21.127/49.452≈**0.427**，仍显著小于 1，结论方向不变；按协议 headline 仍为均值口径的 0.369。
2. **两个 `outer_time` 文件不可混引**：`outer_time_resume.txt` 描述 67 分钟**测量**进程（MaxRSS 84,148,944 KB≈80.2GiB、Swaps 0、%CPU 4328%、exit 0）；`outer_time.txt` 描述 20 分钟**收尾重放**进程（MaxRSS≈80.1GiB、%CPU 2072%、exit 0）。
3. **SD 口径命名**：`results.csv` 的 `api_call_wall_s_std` 是总体 SD（÷N，驱动 `stddev()`）；analyzer 报告的 `api_sample_sd_s` 是样本 SD（÷(N-1)），两者相差 √(10/9)≈1.0541。同名不同义，勿直接互比。
4. **affinity 字段不能当作 pinning 证据**：identity 的 `initial_affinity`/`calling_thread_affinity` 在本机记录为 `"0;"`（libgomp 在 `main()` 读取 affinity 前已把初始线程绑定到 place 0 的表现），与 `taskset -c 0-63` 的启动掩码不能相互印证。pinning 的旁证是 provenance 中两条命令均为 `taskset -c 0-63`，以及测量进程 %CPU 4328%（≈64 核）；“最终绑定到哪些核”未被工件直接记录。
5. **provenance 归因边界**：真正完成最后 5 个 N=32768 配置的测量进程（`resume_campaign.sh`，同命令/同冻结环境）未写入 `resume_events`；`resume_events[0]` 记录的是随后的收尾重放进程（历史工具名 `tools/resume_paper_alignment.py`，02:53:57 完成）。两者 rc=0、身份经 driver 逐 checkpoint 校验一致，数据身份无风险，但“哪个进程产生哪些样本”在 provenance 中不完整，属披露级流程 caveat。
6. **跨进程混样 1 个配置**：`checkpoint.fp64.16384.15.json` 的第 0 对样本来自原进程（00:56–01:03），第 1–9 对来自续跑进程（01:29–01:31）；断点效应检查 sample0/mean(1–9)=0.989（wall）/0.995（mkl），无可见不连续。

第 8 节“剩余缺口”另补一条：达标检查器验证的是**内部一致性 + 身份 + 覆盖**，不是样本真实性。第三方验证确认，一个把某配置全部 wall 样本与其派生列同步改写（自洽伪造）的副本可以通过检查器（exit 0）——检查器没有样本级签名或外部锚点，因此“检查器 rc=0”不能单独作为原始计时未被改写的主张；真实数据的支持来自 checkpoint↔CSV↔identity 的多方一致与本次独立重算。
