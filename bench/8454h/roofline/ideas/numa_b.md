NUMA packed-B replication candidate (isolated clone: /tmp/ozamx-roof-numa-b)

Macro: OZAMX_NUMA_REPLICATE_B=0/1, default 0. Only enters when the computed team size exceeds 32 and min(M,N)>=4096. It retains the original packed B and allocates two additional aligned copies per slice. Linux SYS_getcpu supplies each copy worker's node; one-time node/rank assignment partitions each copy by contiguous 64-byte lines. A node without copy workers is filled by the whole copy team. Each compute worker queries its node once and selects that replica only for node 0 or 1; otherwise it reads original p.b. Copy time is separately exposed and included in pack_seconds. A/B panel indices, product order, private result, and transactional C commit are unchanged.

Cost: adds 2x packed-B storage on top of the original (three packed B sets total), plus allocation and a full copy pass; replication is not a performance win claim. `replicate_b_seconds` and copy-team node counts are included in profiled timings for future paired tests. The 4096x4096, K=1 FP64 p6 validation probe exercised replication with 64 workers and A=B=C aliasing: node0/node1 had 31/33 workers, no getcpu fallback, and the macro-off/on output digests matched. Reported 4.44 ms is a correctness-probe timing only, not a benchmark result.

Gate results: native kernel audit passed; CTest passed 3/3; the 47-case extended suite passed bitwise at 1/4/64 threads with 1 GiB and zero-byte workspace cache; the 100-case equivalence suite passed bitwise at 1/4/64 threads. `numa_b_gate.sh` compares JSON rows incrementally and retains only row hashes so it does not generate large temporary JSONL files.
