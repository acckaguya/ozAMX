Paper: Cui and Liu, arXiv:2609.04663v1, local third_party/papers/2609.04663v1.pdf
Protocol source: docs/REPRODUCTION_SPEC.md and docs/PAPER_STUDY.md
Paper CPU/OS/toolchain: 2-socket Xeon Platinum 8462Y+, Rocky Linux 9.3, Intel oneAPI/oneMKL 2026.1, Intel OpenMP, 64 physical-core threads.
Local host snapshot is in machine_lscpu.txt and machine_uname.txt. Current cpufreq governor and min/max policy are captured separately; current governor was powersave. Current cgroup path came from /proc/self/cgroup; memory.max at the session and parent levels was unlimited (max). Filesystem free space at campaign start: approximately 35 GiB. perf_event_paranoid captured separately.
Inputs: std::mt19937_64 base seed 260904 plus N, uniform [-1,1]. Paper does not specify RNG or seed; this is a reproducibility choice.
Main configurations: 8 sizes x (FP32 p6 + FP64 p6/p10/p15/p21) = 40. One warmup per configuration; full API calls timed 10 times, each raw sample/checkpointed. Per-phase profile is retained by the API. Main driver computes complete oneMKL SGEMM/DGEMM eF and e_scaled and full oneMKL absolute-product denominator; high-precision diagnostic is explicitly sampled for N>256 and is not the paper accuracy result.
Scaling: FP32, N=1024/4096/16384, threads=2/4/8/16/32/64, 18 configurations.
Headroom: oneMKL cblas_gemm_bf16bf16f32 raw BF16 x BF16 -> FP32, 8 configurations. This is not the emulation algorithm. Report actual GFLOP/s and TFLOP/s; paper's Fig. 6 labels its raw values GFLOPS and that label is preserved as a source-unit caveat.
Compiler/runtime difference: local campaign uses GCC 11.4, GNU OpenMP, oneMKL 2026.1 GNU threading and frozen V3 static library built with the GNU toolchain. It does not claim Intel compiler/OpenMP parity with paper.
Timing: input generation, output allocation, MKL reference, and permission setup are outside V3 timing. V3 full API wall sample surrounds the complete profiled API call; phase timings are also output. In this frozen implementation, per-thread tile config remains within compute; record as engineering difference.
V3 preprocessing cache configuration: OZAMX_WORKSPACE_CACHE_BYTES was unset. The original process started with the variable unset and uses the compiled 2 GiB default; the resumable runner now explicitly exports the identical `OZAMX_WORKSPACE_CACHE_BYTES=2147483648` value. `hardware_samples/` captures the Linux `/proc/stat` per-CPU counters and per-CPU current frequency/governor policy around each configuration after watcher start, plus a campaign midrun baseline and campaign-end sample. Benchmark results are from a shared host; the taskset constrains affinity but does not provide exclusive CPU ownership, so background contention and the powersave governor can affect wall times. No PMU/perf sampling or system governor changes were made.
