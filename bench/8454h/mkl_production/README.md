# Final frozen production oneMKL comparison

This is the production-linked oneMKL run, distinct from the isolated eager/1 GiB candidate in `mkl_v2`. It uses the fresh CMake Release library `/tmp/ozamx-production-final/libozamx.a` with SHA-256 `ddfe885c2ba58089accd4e747aecb53a18422554e06fc409965e2f47b7d92251`; its source SHAs are fixed in `provenance.json`. The current production tree and this archive's pre-run SHA manifest matched byte for byte, and the library hash was rechecked after the run. The benchmark driver uses source ID `mkl-wall-production-final-20261013` to isolate checkpoints.

The complete 20-configuration matrix finished successfully: FP32 p6 and FP64 p6/p10/p15/p21 for N=256, 1024, 4096, and 8192. Each row includes five timed repetitions, raw split/pack/compute/profile-total/API-wall samples, population mean and standard deviation for API wall, checksum, errors vs oneMKL and high precision, MKL GEMM mean, runtime version/path, and status. `production_comparison.md` provides the entire v1/final production/MKL table; `full_production.csv` is authoritative for raw data. Twenty complete per-configuration checkpoints are retained.

The run used a first-call warmup per configuration, uniform inputs with seed base 260904 and resolved seed 260904+N, CPUs 0–63, 64 OpenMP/MKL threads, close core binding, GNU MKL threading, and `OZAMX_WORKSPACE_CACHE_BYTES=2147483648`. The full command is in `run_command.txt`; it holds `/tmp/ozamx-perf.lock` over benchmark compilation and the run. Driver flags, CMake defaults, source/library/driver hashes, compile database hash, oneMKL runtime hash, and timing scopes are recorded in `provenance.json`.

API wall includes the complete ozAMX profiled call, dispatch, and teardown. oneMKL timing covers GEMM only; wall/MKL ratios are descriptive and not matched end-to-end application comparisons. The full interpretation, frozen production settings, phase summaries, errors, and all 20 rows are in [the final production report](../../../docs/8454H_FINAL_PERFORMANCE_REPORT.md).
