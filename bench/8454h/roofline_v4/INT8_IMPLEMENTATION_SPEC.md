# INT8 prototype preparation specification

This is isolated source preparation. No compilation or CPU tests until the V3 paper campaign is complete and archived. Production and frozen V3 remain unchanged.

Implement a standalone FP64 INT8-36 experimental backend targeting at least V3 p21 empirical accuracy, with fresh files in `bench/8454h/roofline_v4/int8_proto/`: header, C++ implementation, handwritten GAS kernel, standalone CMake and README. Link frozen V3 runtime for permission and baseline; do not replace public ProductBudget semantics. Thirty-six INT8 products are not called 21 products.

For each operand collect maxabs with SIMD. Let e=frexp(maxabs).exponent, use e=0 for all-zero. Quantize y=RNE(x*2^(55-e)), |y|<2^55. Extract eight balanced base128 digits lowest first: low=((y+64)&127)-64; y=(y-low)/128; reverse to highest-first. Lower digits lie [-64,63], highest [-64,64]; all fit signed int8. Only finite zero or BF16-normal-range source values; prototype may explicitly restrict aligned M,N,K initially, but must not pretend full general API coverage. K<=32768.

Select component pairs i+j<8, 36 products, grouped into eight diagonals. Integer associativity permits K/operand reordering. Accumulate every diagonal across the whole K in an int32 output plane; maximum bound 8*K*64^2<=2^30. Never merge differently weighted diagonals in int32.

Use BK256 initially and private output macro128x128 (compile knobs for BK64/128/256/512 and M/N64/128/256). Per worker keep Cplanes[8][CBM][strideN], row padding64bytes, plane pitch an additional64bytes to change page-offset aliases. Load/store existing INT32 C for each BK and diagonal; no FP32 intermediary and no double reconstruction until all K blocks finish. Working footprint at128x128/BK256 is roughly1MiB for INT32 C+eight input components, within2MiB L2. Then assemble eight diagonal results via signed __int128, weight shift=7*(14-diagonal), and apply power2 exponent eA+eB-110 after one direct int128->double conversion. Do not left-shift negative signed values: multiply sign-extended sums by positive int128(1)<<shift.

Safety proof with assumptions: E=sum|d_i|2^(7i)<=64*(2^56-1)/127<(128/127)*2^55. Thus K*E_A*E_B<(128/127)^2*2^125<2^126 for K<=32768; every weighted partial sum fits signed128 with margin. Finite BF16-normal input extrema give normal FP64 nonzero reconstructed output lattice >=2^-360 and max magnitude<2^272, so scaling does not create FP64 subnormal/overflow. Quantization and omitted products still require an empirical precision gate; this proof is not an accuracy bound. No early long-double conversion causing double rounding.

Packing: A [M32][K64][slice8][32x64=2048B], top/bottom16rows each1024B. B [N32][K64][slice8][64x32=2048B], VNNI4 with left/rightN16 each1024B. SIMD quantize8 doubles to8 int64, seven-bit shifts/masks, pack8 bytes per slice. A direct stores; B consume4 Krows x8Ncols, unpack8 then unpack16 into four-byte K groups and store32B. Padding elements zero. All input data fully packed before caller C is written, so aliasing and transactional failure can be preserved. Use unchanged V3 workspace pool in a clearly compatible namespace or copy it into experimental namespace, with explicit2GiB cache default and complete API accounting; allocation/free included in wholeAPI.

Handwritten one-diagonal GAS ABI: arguments const A_pointer_array[], const B_pointer_array[], int32 Cptr, C_stride_bytes, K64_step_byte_stride, steps, pair_count<=8. Arrays point to initial K64 slice blocks, step stride=8*2048B. Kernel config all8 tiles16rows64bytes: tmm0/1 A16x64 top/bottom, tmm2/3 B VNNI4 left/right, tmm4..7 INT32 C quadrants. Load four existing C tiles once, outer K64 loop and inner pair loop load four input tiles with selectable TILELOADDT1/TILELOADD, issue four TDPBSSD, then store four C tiles. Input tile strides64B, C actual macro row stride. Respect System V callee registers and seventh stack argument offsets. Per-worker tile config and release around computation. Check CPUID AMX_INT8 in addition to Linux permission; do not infer from BF16 alone.

README must distinguish prototype assumptions, correctness obligations, and unresolved work. No CPU execution now. Root will inspect code and start construction after V3 paper freeze. Scalar tail fallback is acceptable, regular quantize/pack/zero/reconstruct use SIMD where appropriate; int128 final weighted assembly may initially be scalar.
