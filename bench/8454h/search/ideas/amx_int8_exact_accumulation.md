# 下一轮：AMX INT8 + 全 K 整数累加

状态：仅设计，尚未实现、验证或测量；不属于本轮生产版本的性能结果。

动机：最终 BF16 路径仍对每个 BK=256、每个 FP64 分量写回 FP32 micro，再 SIMD 扩展并加到 FP64 block。若可以用整数在完整 K 上精确累加，SIMD 还原次数可从 ceil(K/256) 次降低为一次。INT8 的额外点积和输入流量可能抵消收益，必须实测。

## 必须先确认的数值条件

当前 rho45 投影使用正 sigma。`sigma + r` 对负 r 落在 sigma 下方的 binade，间距比正 r 分支小一半。不能把两种符号都简单当作同一个有符号 INT8！候选应先从实际保存的 BF16 片恢复整数与 dyadic scale，逐个元素证明可表示。

在通常的有限正常投影中，统一更细的格点可写成 `h = q * 2^(ceil_log2(residual_max)-8)`，q 的候选界为 [-256,256]。需审计所有允许指数、零、最大 BF16 输入拒绝行为及实际 BF16 RNE 后的值，不以这一模型直接替换已有分解。rho45、BK256 时单组件整数点积的绝对值界为 256*256*256 = 2^24；若所有值确实落在该格点，原组件 FP32 点积可精确表示这些整数。跨 BK 和跨组件的最终 FP64 加法仍会舍入。

把 q 表为 `u + 256*s`，其中 u=q mod 256 为 unsigned byte，s=floor(q/256) 为 signed byte (-1,0,1)。一个组件需要四种整数点积：

- uA*uB：无符号/无符号，权重1；
- sA*uB 与 uA*sB：混合符号，权重256；
- sA*sB：有符号/有符号，权重65536。

四个原始点积分别还原到足够宽的整数，再加权。不能把不同权重的点积直接加进同一个 TMM accumulator。对 K<=65536，uA*uB <=65025*K <2^32；结果须按 uint32 解读，不能因符号位为1误当负数。混合项及 sA*sB 落在 int32 范围内。K 更大要分段，或回退已验证 BF16 路径。

这需要4次 INT8 点积；INT8 K64 与 BF16 K32 的 tile几何不同，算术成本约为现有单组件 BF16 的2倍，输入 tile 流量也可能增加。收益来自省掉大量组件还原，不能只据 INT8 峰值吞吐宣称加速。

## 实现与验收顺序

1. 在隔离树中实现量化格点审计，记录每片 exponent 和全元素 q，确认 `BF16(q*scale)` 逐位恢复原保存片。处理 whole-zero，不对零片捏造有效 exponent。
2. 写 INT8 A16x64、B16x16x4 打包和四种 AMX 点积的独立审计。先逐元素比 int32/uint32 点积与宽整数 oracle，验证 unsigned wrap 的解释、K边界和 padding。
3. 全 K 组件和跨组件 dyadic sum 用至少128位整数；根据 exponent跨度和累加上界检查可容纳性，超过范围回退。AVX512 64位双字可实现带进位的128位累加；最终一次 RN-even 转到 FP64。普通 `double(high)*2^64+double(low)` 可能双重舍入，不能充作正确转换。
4. 此模式重组了 BK/组件的 FP64 加法顺序，不能伪称与生产版逐位一致。须比较 BF16 截断和的整数/float128 oracle、原输入的 float128 样本、全 Frobenius误差、scaled error、极端动态范围、抵消、非法输入、alias、错误时 C不变；按 budget保留独立精度门。
5. profile 1/64线程、4096/8192、p6/p21，全调用 wall、分解/打包/算术/还原、faults、workspace cap。同一轮夹跑当前生产版，失败候选保留原因和原始数据。

更进一步可探索9位对称整数投影（例如按全局幂二格点显式RNE量化），以六层争取约54位而非约48位精度。它改变现有分解，必须独立标为新的算法，并重新验证精度及输入域；本轮没有据此修改生产代码。
